# Live view (handoff)

Embedded `/handoff/` view of any tab, for phones and desktops. Touch: tap to click, drag to scroll, the phone keyboard mirrors the focused field. Mouse and keyboard: drag to select, double/triple click, Ctrl+C/X/V through the local clipboard, Ctrl+A/Z/Y, arrow keys; a capture button (fullscreen + Keyboard Lock) sends browser shortcuts like Ctrl+W to the page. Files dropped onto the view are dropped into the page (Chromium). When the page opens a file chooser (an upload button, or `input.click()` from its script), the view's own chooser opens instead, right away after the click that asked, otherwise from a bar with **Choose…** and **Cancel**; the picked files go into the page's file input (Chromium, and Firefox 139 or later). Without a view connected, the page's chooser is left alone. Works for both engines: Chromium streams a CDP screencast, Firefox streams WebDriver BiDi screenshots.

## Downloads

what a page downloads is saved on its node (`<state dir>/downloads/<session>/`, removed when the session ends) and lands on the viewer's device: a download that starts right after your click or tap in the view is saved by itself once it is done; any other waits in a tray at the bottom with **Save**, and every one of the session's downloads is in the view's session menu (**Downloads**) and the dashboard's session menu (**Downloads…**). Chromium (`Browser.setDownloadBehavior`) and Firefox (WebDriver BiDi `browser.setDownloadBehavior`). An automation client that sets its own download behaviour (Playwright does) keeps it while it is connected; the node still lists those downloads where the client put them, and takes over again when the client leaves. API: `GET /api/sessions/<id>/downloads` lists them, `GET /api/sessions/<id>/downloads/<download>` serves the file (Range requests work), `DELETE` removes one; `browser-daemon session downloads SESSION`, `browser-daemon session download SESSION DOWNLOAD [-o FILE]`.

## Dashboard and live view details

site icons are fetched by the node (`GET /api/favicon?url=<page>`: public http(s) hosts only, raster images up to 256 KB, remembered per origin; a letter where there is none), so no browser contacts a site or an icon service. The live view opens in **Phone** on touch and narrow screens (until you pick another Screen). A password field's text never reaches the view (the phone keyboard mirrors bullets). Taking over a session an agent drives asks first. Dashboard defaults: a new session is **ephemeral** (it stops once its last automation client disconnects; the live view does not hold it); turn **Ephemeral** off for one that runs until stopped. Profiles launched from the Profiles tab, the CLI and the TUI start persistent ones. Defaults on the Engines tab are drafts until **Apply to N nodes** (with a confirmation).

## Vault logins

the key button next to the dashboard button works like the Bitwarden extension's popup and looks like the rbw one: it lists the [rbw](https://github.com/doy/rbw) vault's logins for the page's site (its badge counts them), searches the whole vault, and fills the one you pick into the login form (username and password, or the username alone on a username-first page; **TOTP** fills the one-time code). A passkey sign-in on the page opens a dialog that names the site and the vault entry; approving it signs in with the vault's passkey. The vault stays with the [secret agent](rbw.md#secret-agent), which asks your phone to unlock rbw when it's locked; without one the node has no vault. The view sees names and users; a password or code reaches it only when you copy one (to this device's clipboard), and an entry saved for another site takes a second click. API: `POST /api/sessions/<id>/autofill {"page_id": ...}` lists, `{"page_id": ..., "entry": "<vault id>", "fields": ["username", "password", "totp"]}` fills; both answer `{"request": ...}`, polled at `/api/passkey/<request>`. How the vault is reached, what is checked where and how the styles follow rbw: [rbw vault](rbw.md). The button, popover and prompt are rbw's [live-view extension](extensions.md) (`--extension-dir`; on NixOS the default).
